# Contributing to Templatte

Thank you for helping. Please read the [Code of Conduct](CODE_OF_CONDUCT.md)
first.

## Security issues

Anything touching the crypto engine, the envelope format, passphrase handling or
`.gitignore` coverage must **not** be filed publicly. Follow
[SECURITY.md](SECURITY.md) and report it privately.

## Branch workflow

(See `docs/spec/04_GIT_AND_WORKFLOW_SPEC.md`, section 2.)

- `feat/*` and `fix/*` branches are created from `develop` and merged back into
  `develop` with a **squash merge**: each branch becomes exactly one commit.
- `develop` is merged into `main` with an explicit **merge commit** on release,
  never squashed. Releases are annotated `vX.Y.Z` tags on `main`.
- `main` and `develop` are protected: changes arrive through pull requests with
  the CI workflow passing.

### External contributors

1. Fork the repository.
2. Create a `fix/<short-name>` branch from `develop` in your fork (use
   `feat/<short-name>` for a new capability).
3. Open a pull request **against `develop`**, never `main`.

CI (`.github/workflows/ci.yml`) runs on every push and pull request across
Linux, macOS and Windows and Python 3.10 to 3.13. It needs no secrets, so it
runs unprivileged for fork pull requests.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/):
`<type>(<scope>): <subject>`.

- Types: `feat`, `fix`, `chore`, `docs`, `test`.
- Scope: the area touched, such as `adapters`, `crypto`, `cli`, `services`,
  `registry`.
- Reference the `TASK-ID` from `docs/spec/03_AGENT_HARNESS_AND_TASKS.md` when
  there is one, for example:

  ```
  feat(adapters): implement TOML round-trip preservation (TASK-202)
  ```

  A contribution outside the roadmap has no TASK-ID; say so in the pull request.

## Verify locally

Run all of these before opening a pull request:

```
uv sync
uv run ruff check .
uv run ruff format --check templatte tests
uv run pytest
```

## Never commit secrets

Do not commit `templatte.toml`, `.env`, `.bak` backups or any concrete
configuration file generated by `templatte deploy`, and do not paste them in
issues. Only `*.latte` templates and `templatte.toml.enc` are meant to be
tracked. Test fixtures must contain dummy values only.
